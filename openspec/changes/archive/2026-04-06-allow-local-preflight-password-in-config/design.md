## 上下文

本地 cross-platform preflight 的目标是“帮助开发者尽早发现跨平台问题”，强调高频、低摩擦、可选启用。现状下如果未配置 `identity_file`，`ssh/scp` 会进入交互密码提示，这会让自动化或半自动化执行在本地终端阻塞。

对于该能力而言，密码落盘的讨论边界与生产系统不同：

- 配置文件位于仓库 gitignored 路径（如 `tmp/local-preflight.toml`）
- 能力不作为正式 gate，不进入 release artifact
- 风险控制重点是避免密码被意外传播到跟踪内容、日志、stdout 和命令参数

因此，本变更目标不是“提升通用 SSH 安全模型”，而是“在本地开发工具范围内提供可接受且可控的便利能力”。

## 目标 / 非目标

**目标：**

- 支持在 gitignored 本地配置中提供可选 `password` 字段，实现非交互认证
- 保持认证语义稳定可预期（key 优先、password 次之、最后交互）
- 确保密码不进入日志、summary、示例配置和仓库跟踪内容
- 维持 Linux / Windows 路径一致性（传输 + 执行都能非交互）

**非目标：**

- 不将该密码能力复用于生产运行时、MCP、broker 或 vault 语义
- 不引入远端密码管理、系统级密钥链集成或集中密文存储
- 不改变 preflight “可选本地工具”的定位

## 决策

### 决策 1：配置模型新增可选 `password`，并严格限定在 gitignored 本地配置

在 host 配置中新增可选 `password` 字段。该字段仅允许出现在开发者本地 gitignored 配置中，不允许出现在仓库示例配置中的真实值，也不得被写入任何跟踪文件。

理由：

- 直接满足“本地自测可自动化、不被交互阻塞”的核心诉求
- 保持与现有 TOML 配置风格一致，学习成本低

### 决策 2：认证优先级固定为 `identity_file` > `password` > 交互提示

当配置了 `identity_file` 时，继续使用 key 认证并忽略 `password`；当未配置 key 且配置了 `password` 时，使用非交互密码认证；两者均未配置时保持现有交互提示行为。

理由：

- 与现有文档“优先 key、无 key 才密码提示”的心智一致
- 保持行为确定性，避免“有 key 但偷偷回退密码”导致排障复杂

### 决策 3：密码输入机制必须避免 argv 暴露，并统一日志脱敏

实现非交互密码认证时，禁止把明文密码拼接进命令参数（argv）或日志文本；运行日志中涉及认证模式时只记录“password auth enabled”等脱敏信息，不记录密码值本身。

理由：

- 本地落盘风险可接受，但 argv/log 泄露面仍需最小化
- 与 preflight 既有“本地辅助记录”定位保持一致

### 决策 4：示例与文档显式标注风险边界与推荐实践

example 配置仅保留字段结构与注释，不包含任何真实密码；文档新增“密码仅用于本地开发便利、优先使用 key”的提醒，并说明日志不会记录密码。

理由：

- 降低误用概率，避免贡献者把密码误提交或误认为生产推荐路径

## 风险 / 权衡

- **本地明文落盘风险上升**：通过 gitignored 限制、文档告警、日志脱敏来控制；并继续推荐 key 为首选
- **实现路径的跨平台细节差异**：需要在 Linux/macOS 本地 runner 上验证 `ssh/scp` 密码注入方式一致可用
- **排障可观测性与脱敏冲突**：保留“是否启用 password 模式”的状态信息，但不保留秘密值

## Migration Plan

1. 更新 spec 与 proposal/design/tasks，明确允许本地密码字段与安全边界
2. 修改 preflight runner 配置解析与认证调度，加入 password 模式
3. 更新 example 与 docs，增加字段说明和风险提示
4. 补充回归验证并记录结果

回滚策略：

- 若后续发现维护成本或风险不可接受，可回滚密码字段支持，恢复为 key 或交互提示模式，不影响正式 gate 体系
