## 新增需求

### 需求:macOS 控制台必须为残留 managed core 提供正式恢复入口
在 bundled 默认路径下，macOS 控制台必须把 orphan core、stale endpoint、监听地址占用和 owner 冲突视为正式产品恢复场景。控制台必须提供与 host lifecycle state machine 一致的恢复入口，而不是只展示泛化的连接失败提示。

#### 场景:启动时正在回收 orphan core
- **当** 控制台启动时发现同一 runtime root 下存在需要回收的 orphan core 或 stale discovery artifact
- **那么** 控制台必须展示明确的恢复中状态，并提供重试、查看日志或等价诊断入口，而不是继续显示普通 attach failed 或伪成功主界面

#### 场景:启动时发现活动实例冲突
- **当** 控制台启动时发现一个不满足自动回收策略的活动实例冲突
- **那么** 控制台必须展示可理解的冲突说明与后续动作入口，例如重试、查看诊断或在满足策略时执行显式接管/强制清理，而不是静默失败

## 修改需求

### 需求:macOS 控制台必须展示 bundled core 的启动与连接状态
在 bundled 发行物中，macOS 控制台必须能够反映其托管 core 的启动、实例发现、旧实例探测、orphan 回收、监听资源释放等待、attach、连接失败、目录失效、重启中、冲突与恢复状态，而不是假定 core 永远已经就绪。至少必须覆盖“需要选择 runtime root”、“发现旧实例”、“正在探测旧实例”、“正在回收 orphan core”、“等待监听地址释放”、“正在启动 core”、“等待 attach 完成”、“保存中”、“等待重启”、“重启中”、“冲突待处理”、“重启失败”与“已连接到真实 core”这些状态。

#### 场景:控制台启动时正在探测或回收旧实例
- **当** 用户启动 bundled 控制台，且宿主正在同一 runtime root 下探测旧实例或回收 orphan core
- **那么** 控制台必须展示明确的发现/恢复状态，而不是直接跳到“启动中”或把底层恢复过程完全隐藏

#### 场景:控制台在重启前等待旧实例释放监听资源
- **当** 控制台因设置变更或恢复流程需要重启 managed core，且宿主正在等待旧实例释放 endpoint 或默认监听地址
- **那么** 控制台必须展示明确的等待释放状态，并阻止界面伪装成已经重新连接成功

#### 场景:控制台遇到无法自动解决的实例冲突
- **当** bundled 控制台发现一个无法自动解决的活动实例冲突
- **那么** 控制台必须展示可理解的冲突状态、诊断入口与后续动作，而不是继续回落到过于笼统的连接失败文案

## 移除需求

无。
