## 新增需求

### 需求:长期 token 签发成功后必须提供一次性结果展示
桌面控制台在受信任的设置与安全管理流中成功签发长期 agent token 后，必须立即展示一个正式的一次性结果面板，用于承接本次响应中的明文 token。该面板必须与 token 安全摘要列表分离，至少包含明文 token、copy 动作、以及“关闭或刷新后不会再次显示”的明确提示。系统禁止仅以普通状态消息代替这次一次性结果展示。

#### 场景:用户签发长期 token 后查看一次性结果
- **当** 用户在桌面控制台的 `Settings > Vault` 区域完成本地用户验证并成功签发一个长期 agent token
- **那么** 系统必须展示包含明文 token、token label 或等价签发摘要、copy 动作和一次性展示提示的正式结果面板，而不是只显示“创建成功”状态文本

#### 场景:用户关闭结果面板后查看 token 列表
- **当** 用户关闭一次性结果面板、刷新 token 摘要列表，或重新进入设置与安全管理区域
- **那么** 系统必须继续只显示 token 的 display-safe 摘要，而不得从 token 列表、普通刷新或其他非签发响应路径再次回显该明文 token

#### 场景:copy 动作不可用时仍保留本次结果
- **当** 用户在一次性结果面板中触发 copy，但当前宿主环境无法完成 clipboard 写入
- **那么** 系统必须保留当前可见的明文 token，并向用户返回明确的 copy 失败反馈，而不是让这次一次性结果消失
