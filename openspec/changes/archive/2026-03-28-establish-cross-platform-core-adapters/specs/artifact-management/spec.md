## ADDED Requirements

### 需求:宿主平台产生的文本输出必须经过兼容解码与换行归一化
系统在采集本地 shell、connector 或 provider 产生的文本输出并写入 artifact 时，必须采用宿主平台兼容的文本解码与换行归一化策略。系统不得默认把所有平台输出都当成标准 UTF-8 / LF 文本处理，并在无法可靠解码时必须提供明确诊断。

#### 场景:Windows 宿主采集非 UTF-8 输出
- **当** BridgingIO core 运行在 Windows，且本地 shell 或外部工具输出包含当前平台编码下的非 ASCII 文本
- **那么** 系统必须尽可能以宿主平台兼容方式解码并写入 artifact，或返回明确的解码诊断，而不是静默生成已损坏的文本内容

#### 场景:跨平台统一读取 artifact 文本
- **当** UI 或 MCP 客户端读取由不同宿主平台生成的文本 artifact
- **那么** 系统必须提供一致的换行归一化与可阅读文本结果，而不是让调用方自行适配 `CRLF`、`LF` 或混合编码差异
