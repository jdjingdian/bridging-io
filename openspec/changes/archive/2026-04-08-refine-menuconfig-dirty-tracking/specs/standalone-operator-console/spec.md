无

## 修改需求

### 需求:operator console 必须尽量对齐 Linux kernel `menuconfig` 的核心交互模式
BridgingIO 的 `menuconfig` 操作面必须尽量对齐 Linux kernel `menuconfig` 的核心交互模式，至少覆盖树形导航、帮助面板、搜索入口、dirty tracking、保存/应用语义，以及单栏逐级进入的主界面组织方式。这里的 dirty tracking 必须反映“当前内存草稿相对本次会话基线配置是否仍存在真实差异”，而不是单纯记录某个字段曾经被编辑过。

#### 场景:主流程保持单栏逐级进入
- **当** 操作员从主菜单进入任一子页面、详情页或管理流程
- **那么** 系统必须通过 `--->` 与 `Enter` 进入下一级单栏页面或 centered popup，而不是切换到分栏主界面或并排工作区

#### 场景:popup 优先拦截 `Esc`
- **当** 操作员当前位于确认弹窗、帮助弹窗、文本输入弹窗或单选弹窗中并按下 `Esc`
- **那么** 系统必须先关闭当前 popup 或取消当前流程，而不是把 `Esc` 直接穿透成上一层菜单返回

#### 场景:字段改回基线后退出不再提示保存
- **当** 操作员在 `menuconfig` 中临时修改某个普通配置字段，随后又把该字段恢复为进入会话时的基线值
- **并且** 当前整体配置相对本次会话基线已不存在真实差异
- **那么** 系统必须移除根页面 dirty 标记
- **并且** 当操作员在根页面按下 `Esc` 或触发 `Exit` 时，系统不得再弹出保存确认

#### 场景:仍有真实未保存差异时退出必须确认
- **当** 操作员在 `menuconfig` 中修改了一个或多个配置项，且当前整体配置相对本次会话基线仍存在真实差异
- **那么** 系统必须明确显示存在未保存修改，并在根页面 `Esc` 或 `Exit` 时弹出 `Yes/No/Cancel` 保存确认弹窗
- **并且** 系统不得因为某些字段曾被改回原值就错误忽略其他仍未保存的真实差异
