## 为什么

当前 macOS SwiftUI 项目仅支持英文，界面展示文本存在直接硬编码，导致产品无法满足中文用户使用场景，也让后续文案维护和扩展语言成本偏高。现在引入基于 `Localizable` 的国际化基线，可以在保持产品名一致的前提下，快速完成中英文双语支持并消除显示层硬编码风险。

## 变更内容

- 为 macOS SwiftUI 项目建立 `Localizable` 多语言资源体系，首批支持 `en` 与 `zh-Hans`。
- 将所有用户可见文本从视图与组件代码中抽离到本地化资源，不允许继续在显示项中硬编码文案。
- 统一产品名展示规则：中文与英文环境下产品名均显示为 `Bridging IO`，不引入中文别名。
- 定义缺失翻译时的回退行为与开发校验要求，避免新增界面再次出现硬编码文本。

## 功能 (Capabilities)

### 新增功能

无。

### 修改功能

- `macos-operator-console`: 为 macOS 控制台增加基于 `Localizable` 的中英文国际化能力，约束所有显示文本走本地化键值映射，并统一产品名为 `Bridging IO`。

## 影响

- 影响 `source/ui/swiftui-macos` 下的 SwiftUI 视图与通用 UI 组件文案加载方式。
- 需要新增或更新 `Localizable` 资源文件（英文、简体中文）及本地化键命名规范。
- 需要补充静态检查或测试策略，确保新增显示项不再引入硬编码字符串。
- 需要同步更新与 UI 文案相关的测试用例、预览与文档说明。
