## 上下文

当前 `source/ui/swiftui-macos/BridgingIO` 中存在大量用户可见英文文案，主要分布在 SwiftUI `Text/Label/Button`、输入占位符、弹窗标题、校验提示，以及 `Domain`/`ViewModel` 中的 `title` 计算属性。项目尚未建立 `Localizable` 资源与本地化键管理约束，因此新增界面继续出现硬编码文本的风险较高。

本次变更要求：
- 首批语言必须覆盖英文与中文（简体）。
- 显示项禁止硬编码字符，必须经由本地化资源解析。
- 产品名在中英文环境下都统一显示为 `Bridging IO`。

## 目标 / 非目标

**目标：**

- 在 macOS SwiftUI 项目中建立可扩展的 `Localizable` 本地化基线，并落地 `en` 与 `zh-Hans`。
- 将所有用户可见文案迁移到本地化键，禁止在显示路径直接写死展示字符。
- 建立缺失翻译回退与一致性校验，避免后续改动破坏双语体验。
- 明确产品名键值策略，确保所有界面均显示 `Bridging IO`。

**非目标：**

- 本次不引入第三种语言或远端动态翻译平台。
- 本次不重构业务逻辑与 UI 布局，仅处理展示文案国际化。
- 本次不更改品牌命名策略，不提供中文产品别名。

## 决策

### 决策 1：统一使用 `Localizable` 作为默认文案源，并采用 String Catalog 管理双语

实现采用 Xcode String Catalog（`Localizable.xcstrings`）作为默认表，语言仅启用 `en` 与 `zh-Hans`。  
所有需要展示的文案键都在同一 catalog 维护，避免散落多份字符串文件导致键冲突和漏翻译。

备选方案：
- 继续使用分散的 `Localizable.strings`：可行，但键管理和批量审查体验较弱。
- 远端配置中心下发文案：超出当前离线桌面应用范围，复杂度不匹配。

### 决策 2：引入类型化本地化访问层，UI 禁止直接写展示文本

新增统一入口（例如 `L10n` 命名空间），由它暴露本地化键而不是直接在视图中写展示文本。  
SwiftUI 组件通过 `LocalizedStringResource` 或等价本地化 API 渲染文案，带变量的句子统一走格式化键，不允许拼接硬编码展示文本。

落地约束：
- `Text/Label/Button/TextField` 等显示 API 必须优先使用 `L10n` 提供的键。
- 枚举 `title`、校验提示、状态文案等也必须改为本地化键映射。
- 开发示例与模板统一改成“键调用”而不是“字面量文案”。

备选方案：
- 允许 `Text("literal")` 与键方式混用：短期改造快，但会持续引入硬编码回流。

### 决策 3：用静态校验防止硬编码回归

增加一条本地静态校验（lint 或脚本），扫描常见 UI 显示调用中的字面量用法并阻断提交。  
同时增加键一致性检查，确保 `en` 与 `zh-Hans` 键集合一致；缺失翻译时至少回退到英文。

备选方案：
- 仅依赖 Code Review 人工检查：成本高且容易漏检。

### 决策 4：产品名以专用键统一管理，双语值均为 `Bridging IO`

新增品牌键（例如 `branding.product_name`），英文与中文值都固定为 `Bridging IO`。  
应用标题、工具栏品牌位、空状态与提示文案中涉及产品名的场景，统一从该键读取，避免未来出现 `BridgingIO`、`Bridging IO`、中文别名混用。

备选方案：
- 在代码中保留常量字符串：会绕过本地化管线，不满足“显示项禁止硬编码”的目标。

## 风险 / 权衡

- [风险] 迁移范围覆盖视图和 ViewModel，改动点多，容易漏网  
  → 缓解措施：按模块清单迁移并增加 lint + 键一致性检查双保险。

- [风险] 键命名不规范会导致后续维护困难  
  → 缓解措施：制定分层键前缀（如 `workspace.toolbar.*`、`settings.cache.*`、`validation.*`）并在评审中强制执行。

- [风险] 格式化文案（带变量）如果处理不当会破坏多语言语序  
  → 缓解措施：使用参数化本地化模板，不在代码中拼接完整展示句子。

## Migration Plan

1. 启用 `en` 与 `zh-Hans` 本地化配置，新增 `Localizable` 字符串目录（String Catalog）。
2. 新增 `L10n` 访问层与键命名约定，先覆盖全局高频文案（工具栏、侧栏、设置页）。
3. 批量迁移剩余显示路径（视图、枚举标题、校验消息、空状态、按钮标签、占位符）。
4. 新增品牌键并替换现有产品名展示入口，保证全部显示 `Bridging IO`。
5. 增加静态校验：硬编码显示文案检测 + `en/zh-Hans` 键一致性检查。
6. 补充 UI Test/单测断言，验证语言切换后关键页面文案可正确解析。
