## 新增需求

### 需求:原始输出必须缓存为 Artifact
系统必须将命令执行结果、日志输出和流式文本输出保存为可寻址的 artifact，而不是仅以一次性字符串直接返回给调用方。每个 artifact 必须包含稳定标识、来源命令或来源会话、创建时间和内容摘要。

#### 场景:终端命令产生长文本输出
- **当** 用户或 MCP 客户端执行一个会产生大量文本的命令
- **那么** 系统必须创建一个原始 artifact，并返回其标识与适合首轮查看的摘要或预览内容

### 需求:必须支持基于现有 Artifact 的二次过滤
系统必须允许调用方基于已有 artifact 标识创建派生 artifact，并且必须支持关键字、正则、行范围或时间范围等过滤条件。只要原始 artifact 仍然可用，系统就禁止为了调整过滤条件而强制重新执行原始命令。

#### 场景:扩大日志过滤范围
- **当** 调用方基于已有 artifact 发现首次过滤结果过窄，并提交新的过滤条件
- **那么** 系统必须基于已有 artifact 生成新的派生 artifact，而不是重新连接目标并重跑原始命令

### 需求:流式输出必须支持分块续读
对于持续增长或超长的输出流，系统必须以分块方式保存内容，并且必须允许调用方按偏移、批次或续读标记获取后续内容。系统不得要求调用方重复读取已经消费过的块。

#### 场景:读取持续输出的日志流
- **当** 调用方查看一个仍在持续写入的日志 artifact
- **那么** 系统必须返回当前可见的预览内容和续读方式，使调用方能够仅请求新增块
