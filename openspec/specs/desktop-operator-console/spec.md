## 需求
### 需求:桌面控制台必须由 Tauri Shell 作为本地 GUI 宿主
跨平台桌面控制台必须采用 Tauri Shell 作为本地 GUI 宿主，并由其托管 bundled webview 管理面。宿主必须负责托盘或等价驻留入口、窗口打开 / 聚焦、系统通知、本地目录选择、本地 control-plane 桥接，以及 managed core 生命周期管理。桌面管理面禁止依赖额外本地 HTTP 管理端口作为默认工作路径。

#### 场景:用户通过托盘打开管理窗口
- **当** 用户点击桌面应用的托盘图标或等价驻留入口
- **那么** 宿主必须打开或聚焦同一个 bundled webview 管理窗口，而不是要求用户自行访问某个 localhost 管理地址

#### 场景:修改 model-plane 端口后继续管理应用
- **当** 用户在设置中保存新的 core 监听 host/port 并触发受控重启
- **那么** 桌面管理面必须继续通过本地宿主与 control-plane 展示重启与恢复状态，而不是要求 UI 依赖额外本地 HTTP 管理端口完成跳转

### 需求:首次启动必须提供 runtime root 引导流程
跨平台桌面控制台首次启动时必须先进入独立的引导界面，引导用户选择 runtime 数据根目录，并解释该目录的用途、权限预期与后续恢复语义。引导页必须与主工作台分离，且禁止把“尚未选择目录”的状态伪装成已连接主界面。在未配置有效目录前，系统不得允许用户进入主工作台。

#### 场景:首次启动尚未选择数据目录
- **当** 用户首次启动桌面控制台，且本地尚未保存 runtime 数据根目录
- **那么** 系统必须显示独立的引导界面，并提供明确的目录选择入口，而不是直接进入 Targets、Timeline 或 Settings 主界面

#### 场景:引导页不存在进入主界面的取消路径
- **当** 用户仍处于首次启动引导流程，且当前尚未选择有效的 runtime 数据根目录
- **那么** 系统不得提供可绕过配置直接进入主工作台的 cancel 或 continue 路径；唯一的前进路径必须是完成有效目录选择

#### 场景:已保存目录失效
- **当** 宿主检测到已保存的 runtime 根目录不存在、不可写或权限已失效
- **那么** 系统必须回到恢复态引导流程，提示用户重新选择目录或修复权限，而不是静默回退到随机临时目录

### 需求:主工作台必须采用清晰的一级信息架构
跨平台桌面控制台在进入主工作台后，必须至少提供 `Targets`、`Timeline` 与 `Settings` 三个一级入口，并保持它们的职责清晰分离。target 管理禁止继续与时间线审计或设置管理混排在同一主视图中。

#### 场景:用户切换到 target 管理
- **当** 用户在主工作台中进入 `Targets`
- **那么** 系统必须展示独立的 target 列表与详情 / 编辑区域，而不是把 target 表单与 timeline 事件流混在同一主区域

#### 场景:用户切换到设置管理
- **当** 用户在主工作台中进入 `Settings`
- **那么** 系统必须展示独立的设置与安全管理区域，而不是要求用户回到 target 详情页或其他不相关页面寻找 core 参数与 vault/token 入口

### 需求:时间线页面必须先选择被审计使用方，再展示执行卡片
桌面控制台的 `Timeline` 页面必须先让用户选择当前被审计的使用方，再展示该使用方对应的执行简述卡片列表。被审计使用方必须优先按 token label 分组；若请求未配置 token，则必须回落到按 HTTP 请求指纹或 user-agent 等稳定来源摘要分组。卡片点击后必须进入独立详情界面，而不是在列表中直接展开完整输出。

#### 场景:请求携带带标签的 token
- **当** 某批 model-plane 请求由带有 label 的 agent token 认证
- **那么** Timeline 必须先把这些请求归入对应 token label 的使用方分组，并在选中该使用方后展示其执行卡片列表，而不是与其他请求混成一个全局流水

#### 场景:请求未携带 token
- **当** 某批 model-plane 请求未携带 token，或当前运行模式没有 token 认证信息可用
- **那么** Timeline 必须按稳定请求指纹、user-agent 摘要或等价来源摘要为这些请求建立使用方分组，而不是把它们全部显示成无法区分来源的匿名条目

#### 场景:用户点击执行卡片进入详情
- **当** 用户在已选使用方下点击某一张执行简述卡片
- **那么** 系统必须进入该次执行的独立详情界面，并展示命令摘要、target、审批上下文、artifact 关系与按需 transcript 片段，而不是在列表中直接平铺所有细节

### 需求:设置界面必须提供 core、storage、token 与 vault 管理入口
桌面控制台的 `Settings` 页面必须至少覆盖 core 监听参数、日志大小、缓存大小、token 摘要列表与 revoke、以及 vault 管理入口。用户在进入 vault 管理前，必须能够先查看当前已有 token 的安全摘要，并能执行 revoke；系统不得要求后续 UI 自行拼装这些安全管理链路。

#### 场景:用户修改 core 与存储参数
- **当** 用户在 `Settings` 页面修改 core 监听端口、日志大小或缓存大小
- **那么** 系统必须在同一设置区域中提供这些字段的读取、编辑与保存反馈，而不是分散到多个不相关页面

#### 场景:用户查看 token 并执行 revoke
- **当** 用户进入 `Settings` 页面中的安全管理区域
- **那么** 系统必须先展示现有 token 的安全摘要列表，并提供 revoke 入口，而不是要求用户先进入 vault 深层页面后才能看到 token 状态

#### 场景:用户进入 vault 管理
- **当** 用户从 `Settings` 页面进入 vault 管理区域
- **那么** 系统必须展示当前 vault 状态、锁定状态和可执行管理动作，而不是只给出一个抽象入口而没有正式的管理界面

### 需求:桌面控制台必须由仓库内可运行的 Tauri 项目交付
跨平台桌面控制台必须由仓库内正式维护的 Tauri 宿主项目交付，而不是仅由静态 bundled webview 页面、空目录骨架或合同测试代表“已实现”。该宿主项目必须能够在受支持宿主平台上完成窗口创建、页面装载、runtime root 启动分流、bundled core sidecar 启动与本地 control-plane attach。

#### 场景:仓库包含正式宿主工程
- **当** 团队交付跨平台桌面控制台实现
- **那么** 仓库中必须存在可构建、可运行的 Tauri 宿主项目结构，包括宿主入口、窗口配置、权限配置与 sidecar 打包配置，而不是只保留 `src-tauri` 空目录或文档占位

#### 场景:宿主启动后按正式链路进入工作台
- **当** 操作员在受支持宿主平台上启动桌面控制台
- **那么** 宿主必须先解析 runtime root 启动状态，再按需进入 onboarding 或 recovery，并且仅在 managed core sidecar 启动、UI attach 与 bootstrap 完成后进入主工作台，而不是直接加载一个与真实 core 生命周期脱钩的静态页面

### 需求:bundled webview 资产必须存在单一真相源
跨平台桌面控制台的 bundled webview 资产必须以单一真相源维护。系统禁止长期同时维护两份人工编辑的 `index.html`、`onboarding.html` 或等价静态资产并依赖比对测试保持一致。任何宿主内嵌副本都必须由单一来源生成或同步，而不是独立演化。

#### 场景:更新 onboarding 或 workspace 页面
- **当** 团队修改 onboarding、workspace 或 settings-vault 相关 bundled 页面
- **那么** 修改必须落在单一来源并通过生成、复制或打包链路进入宿主发行物，而不是要求开发者同时手工维护 UI 目录和宿主资产目录中的双份 HTML

#### 场景:宿主读取 bundled 页面
- **当** Tauri 宿主启动并装载 bundled webview
- **那么** 宿主必须读取由单一真相源产出的页面资产，使页面路由、bridge command 和 contract snippet 与源码保持一致，而不是依赖可能已经漂移的历史拷贝

### 需求:长期 token 签发成功后必须提供一次性结果展示
桌面控制台在受信任的设置与安全管理流中成功签发长期 agent token 后，必须立即展示一个正式的一次性结果面板，用于承接本次响应中的明文 token。该面板必须与 token 安全摘要列表分离，至少包含明文 token、copy 动作、以及“关闭或刷新后不会再次显示”的明确提示。系统禁止仅以普通状态消息代替这次一次性结果展示。

#### 场景:用户签发长期 token 后查看一次性结果
- **当** 用户在桌面控制台的 `Settings > Vault` 区域完成本地用户验证并成功签发一个长期 agent token
- **那么** 系统必须展示包含明文 token、token label 或等价签发摘要、copy 动作和一次性展示提示的正式结果面板，而不是只显示“创建成功”状态文本

#### 场景:用户关闭结果面板后查看 token 列表
- **当** 用户关闭一次性结果面板、刷新 token 摘要列表，或重新进入设置与安全管理区域
- **那么** 系统必须继续只显示 token 的 display-safe 摘要，而不得从 token 列表、普通刷新或其他非签发响应路径再次回显该明文 token

#### 场景:copy 动作不可用时仍保留本次结果
- **当** 用户在一次性结果面板中触发 copy，但当前宿主环境无法完成 clipboard 写入
- **那么** 系统必须保留当前可见的明文 token，并向用户返回明确的 copy 失败反馈，而不是让这次一次性结果消失
