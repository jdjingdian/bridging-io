## 需求
### 需求:macOS 控制台必须展示目标与会话状态
macOS SwiftUI 控制台必须提供目标列表和会话详情视图，并且必须展示目标类型、连接状态、最近活动时间、环境指纹摘要和能力摘要。

#### 场景:查看已连接目标的会话详情
- **当** 用户在控制台中选中一个已连接目标
- **那么** 系统必须显示该目标的当前会话状态、环境摘要和可用能力，而不是只显示一块空白终端区域

### 需求:macOS 控制台必须提供目标设置入口
macOS SwiftUI 控制台不能只承担审计展示职责，还必须提供目标/profile 的受控设置入口。该入口在 MVP 中至少必须覆盖 SSH/ADB 目标的创建与编辑、SSH 连接信息修改、凭据引用选择、调用别名或模型提示编辑，以及用户备注维护。

#### 场景:编辑 SSH 目标并选择凭据引用
- **当** 用户在控制台中修改某个 SSH 目标的主机地址、端口、用户名、调用别名，并为其选择一个 SSH 密钥引用
- **那么** 控制台必须提供清晰的编辑和保存流程，并展示最终生效的是结构化目标字段与凭据引用，而不是一段自由拼接的命令文本

### 需求:macOS 控制台必须展示工具来源与连接诊断
macOS SwiftUI 控制台必须能够展示当前连接器或 provider 依赖工具的来源和诊断结果，并在职责清晰的界面边界内提供 target 级与全局级覆盖路径设置入口。target 编辑页只允许编辑当前 target 相关工具的局部 override；全局默认值必须在系统设置页编辑。来源至少必须覆盖“target 级用户覆盖”、“全局用户覆盖”、“系统 PATH”和“内置后备”四种状态。

#### 场景:查看当前 ADB 来源
- **当** 用户在控制台中查看某个 ADB 目标或相关诊断信息
- **那么** 控制台必须显示当前生效的 ADB 工具路径与来源类型，并让用户区分其来自 target override、global override、系统安装还是内置后备

#### 场景:编辑 SSH target 时只显示 SSH override
- **当** 用户打开一个 SSH target 的编辑界面
- **那么** 控制台必须只显示 `ssh` 相关的 target override 输入项，而不是同时显示 `adb` 或其他与当前 target 无关的工具项

#### 场景:编辑 ADB target 时只显示 ADB override
- **当** 用户打开一个 ADB target 的编辑界面
- **那么** 控制台必须只显示 `adb` 相关的 target override 输入项，而不是同时显示 `ssh` 或其他与当前 target 无关的工具项

#### 场景:target 诊断区分 target 与 global
- **当** 用户查看某个 target 的工具来源诊断，且该 target 同时存在全局默认值与 target 局部 override
- **那么** 控制台必须能够区分展示 target override、global override 与最终生效路径，而不是只显示一条无法判断来源层级的 effective path

### 需求:macOS 控制台必须在系统设置中管理全局工具来源默认值
macOS 控制台必须在正式设置界面中提供全局 `toolchains.<name>.path_override` 的查看与编辑入口，并将其作为系统级默认值与 model-plane host/port 同级展示，而不是混入 target 编辑页或工作台 target 详情页。

#### 场景:用户在设置界面修改全局 ADB 默认值
- **当** 用户在设置界面中保存新的全局 `toolchains.adb.path_override`
- **那么** 控制台必须通过 core-owned settings 接口提交该修改，并在刷新后让未配置 target override 的 ADB target 看到新的全局默认来源

#### 场景:工作台 target 详情页不再承担全局写入口
- **当** 用户在工作台主界面查看某个 target 的工具来源卡片
- **那么** 控制台必须将该区域定位为诊断展示，而不是继续把全局 override 的直接编辑入口放在 target 详情页中

### 需求:命令交互必须以可折叠时间线展示
控制台必须以事件时间线或命令卡片的形式展示 AI 与目标的交互过程。每个命令事件必须至少包含请求时间、执行状态、摘要、stdout/stderr 的查看入口以及关联 artifact 标识。

#### 场景:命令产生大量输出
- **当** 某条命令产生超长输出
- **那么** 控制台必须默认展示摘要或折叠视图，并允许用户展开查看原始输出或跳转到 artifact 详情

### 需求:macOS 控制台必须提供 artifact cache 设置入口
macOS SwiftUI 控制台必须允许用户查看并配置 artifact cache 的关键参数。MVP 至少必须覆盖 backend 选择、持久化根目录、最大缓存限制、淘汰策略，以及修改后是否需要重启 core 生效的反馈。

#### 场景:用户切换 artifact cache backend
- **当** 用户在控制台中将 artifact cache 从 `memory` 切换为 `filesystem`
- **那么** 控制台必须展示相关配置项与生效条件，而不是要求用户手动修改底层配置文件

#### 场景:用户查看当前缓存占用
- **当** 用户在控制台中查看 artifact cache 设置
- **那么** 控制台必须能够展示当前已使用空间、缓存上限或等价诊断信息，并提供清理入口或后续操作提示

### 需求:macOS 控制台必须支持基于 artifact hash 的反查
控制台在展示 artifact 详情、命令时间线或会话视图时，必须显示稳定 artifact hash，并允许用户基于该 hash 反查来源命令、所属会话、所属通道与派生关系。

#### 场景:用户根据 artifact hash 回溯一次执行
- **当** 用户持有某个 artifact hash，并希望确认它对应的是哪次命令执行
- **那么** 控制台必须能够展示该 artifact 的来源命令、摘要、所属会话/通道与相关执行上下文，而不是只显示一串不可点击的标识

### 需求:审批与敏感操作反馈必须可见
控制台必须展示待处理审批、审批结果以及与命令相关的敏感操作反馈。用户必须能够在控制台中区分“等待审批”、“已批准执行”和“被拒绝执行”等状态。

#### 场景:命令等待用户批准
- **当** 某条命令因策略要求进入审批流程
- **那么** 控制台必须显示清晰的审批状态和上下文，直到该请求被批准、拒绝或超时结束

### 需求:macOS 控制台显示文案必须通过 Localizable 资源解析
macOS SwiftUI 控制台中的用户可见文本必须通过 `Localizable` 本地化键解析，并且必须经由统一入口 `L10n` 调用，显示路径禁止硬编码展示字符。该约束必须覆盖标题、按钮、标签、占位符、空状态、状态文案与校验提示。

#### 场景:工具栏文案渲染
- **当** 控制台渲染工具栏中的应用标题、搜索占位符与操作按钮
- **那么** 系统必须通过 `L10n` 从 `Localizable` 键读取并渲染文案，而不是在 SwiftUI 视图中直接写入展示字符串

### 需求:macOS 控制台必须提供英文与简体中文文案
macOS SwiftUI 控制台必须至少支持 `en` 与 `zh-Hans` 两种语言，并且同一功能页面在两种语言下都必须有可用本地化文案。

#### 场景:系统语言切换到简体中文
- **当** 操作系统语言为简体中文并启动控制台
- **那么** 控制台必须优先显示 `zh-Hans` 文案；对于缺失的键必须回退到英文值，而不是显示键名或空白文本

### 需求:产品名在所有语言环境中必须统一为 Bridging IO
控制台中涉及产品名称的所有展示位置必须使用同一品牌键，并且英文与简体中文环境下都必须显示 `Bridging IO`。

#### 场景:中英文环境下查看产品标题
- **当** 用户分别在英文与简体中文环境下查看应用标题或品牌位
- **那么** 系统必须显示完全一致的产品名 `Bridging IO`，禁止显示其他拼写或中文别名

### 需求:新增显示文案必须通过本地化校验
项目必须提供自动化校验以阻止新增硬编码显示文案，并验证 `en` 与 `zh-Hans` 的键集合一致性。

#### 场景:提交包含硬编码显示文本的 UI 变更
- **当** 新增或修改代码在显示路径中直接写入用户可见字面量文本
- **那么** 校验流程必须失败并提示修复，要求改为本地化键调用后方可通过

### 需求:macOS 控制台必须以 core 真实状态作为运行时真相源
macOS SwiftUI 控制台在产品运行时必须通过受信任的本地 control-plane 读取 core 真实状态，而不是默认展示预置 target、预置 timeline、预置 artifact、预置 approval 或其他示例性业务数据。若 core 当前没有真实数据，控制台必须展示正式空态、加载态或错误态。

#### 场景:首次启动时 core 没有任何目标数据
- **当** 用户启动控制台并成功连接 core，但 core 当前没有任何 target、session 或 artifact
- **那么** 控制台必须展示正式空态，而不是自动渲染示例目标、示例命令历史或示例日志输出

#### 场景:core 返回真实目标与会话数据
- **当** 控制台从 core 读取到真实的 target、session、timeline 或 approval 数据
- **那么** 控制台必须基于这些真实数据渲染界面，而不是继续保留与真实状态无关的预置展示内容

### 需求:macOS 控制台必须展示 bundled core 的启动与连接状态
在 bundled 发行物中，macOS 控制台必须能够反映其托管 core 的启动、attach、连接失败与恢复状态，而不是假定 core 永远已经就绪。至少必须覆盖“正在启动 core”、“等待 attach 完成”、“attach 失败”与“已连接到真实 core”这些状态。

#### 场景:控制台等待 bundled core 完成 attach
- **当** 用户启动 bundled 控制台，且受托管 core 尚在启动或等待 attach 完成
- **那么** 控制台必须展示明确的启动中或连接中状态，而不是立即进入看似已有真实数据的主界面

#### 场景:控制台连接 bundled core 失败
- **当** bundled 控制台启动 core 或 attach core 失败
- **那么** 控制台必须展示可理解的失败状态与后续恢复入口，而不是继续显示过期 seed 内容或空白的伪成功界面
