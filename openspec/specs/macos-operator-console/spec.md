## 需求
### 需求:macOS 控制台必须展示目标与会话状态
macOS SwiftUI 控制台必须提供目标列表和会话详情视图，并且必须展示目标类型、连接状态、最近活动时间、环境指纹摘要和能力摘要。

#### 场景:查看已连接目标的会话详情
- **当** 用户在控制台中选中一个已连接目标
- **那么** 系统必须显示该目标的当前会话状态、环境摘要和可用能力，而不是只显示一块空白终端区域

### 需求:macOS 控制台必须提供目标设置入口
macOS SwiftUI 控制台不能只承担审计展示职责，还必须提供目标/profile 的受控设置入口。该入口在 MVP 中至少必须覆盖 SSH/ADB 目标的创建与编辑、SSH 连接信息修改、凭据引用选择、调用别名或模型提示编辑，以及用户备注维护。

#### 场景:编辑 SSH 目标并选择凭据引用
- **当** 用户在控制台中修改某个 SSH 目标的主机地址、端口、用户名、调用别名，并为其选择一个 SSH 密钥引用
- **那么** 控制台必须提供清晰的编辑和保存流程，并展示最终生效的是结构化目标字段与凭据引用，而不是一段自由拼接的命令文本

### 需求:macOS 控制台必须展示工具来源与连接诊断
macOS SwiftUI 控制台必须能够展示当前连接器/Provider 依赖工具的来源和诊断结果，并在策略允许的前提下提供用户覆盖路径的设置入口。来源至少必须覆盖“用户覆盖路径”、“系统 PATH”和“内置后备”三种状态。

#### 场景:查看当前 ADB 来源
- **当** 用户在控制台中查看某个 ADB 目标或相关诊断信息
- **那么** 控制台必须显示当前生效的 ADB 工具路径与来源类型，并让用户区分其来自用户覆盖、系统安装还是内置后备

### 需求:命令交互必须以可折叠时间线展示
控制台必须以事件时间线或命令卡片的形式展示 AI 与目标的交互过程。每个命令事件必须至少包含请求时间、执行状态、摘要、stdout/stderr 的查看入口以及关联 artifact 标识。

#### 场景:命令产生大量输出
- **当** 某条命令产生超长输出
- **那么** 控制台必须默认展示摘要或折叠视图，并允许用户展开查看原始输出或跳转到 artifact 详情

### 需求:macOS 控制台必须提供 artifact cache 设置入口
macOS SwiftUI 控制台必须允许用户查看并配置 artifact cache 的关键参数。MVP 至少必须覆盖 backend 选择、持久化根目录、最大缓存限制、淘汰策略，以及修改后是否需要重启 core 生效的反馈。

#### 场景:用户切换 artifact cache backend
- **当** 用户在控制台中将 artifact cache 从 `memory` 切换为 `filesystem`
- **那么** 控制台必须展示相关配置项与生效条件，而不是要求用户手动修改底层配置文件

#### 场景:用户查看当前缓存占用
- **当** 用户在控制台中查看 artifact cache 设置
- **那么** 控制台必须能够展示当前已使用空间、缓存上限或等价诊断信息，并提供清理入口或后续操作提示

### 需求:macOS 控制台必须支持基于 artifact hash 的反查
控制台在展示 artifact 详情、命令时间线或会话视图时，必须显示稳定 artifact hash，并允许用户基于该 hash 反查来源命令、所属会话、所属通道与派生关系。

#### 场景:用户根据 artifact hash 回溯一次执行
- **当** 用户持有某个 artifact hash，并希望确认它对应的是哪次命令执行
- **那么** 控制台必须能够展示该 artifact 的来源命令、摘要、所属会话/通道与相关执行上下文，而不是只显示一串不可点击的标识

### 需求:审批与敏感操作反馈必须可见
控制台必须展示待处理审批、审批结果以及与命令相关的敏感操作反馈。用户必须能够在控制台中区分“等待审批”、“已批准执行”和“被拒绝执行”等状态。

#### 场景:命令等待用户批准
- **当** 某条命令因策略要求进入审批流程
- **那么** 控制台必须显示清晰的审批状态和上下文，直到该请求被批准、拒绝或超时结束

### 需求:macOS 控制台显示文案必须通过 Localizable 资源解析
macOS SwiftUI 控制台中的用户可见文本必须通过 `Localizable` 本地化键解析，并且必须经由统一入口 `L10n` 调用，显示路径禁止硬编码展示字符。该约束必须覆盖标题、按钮、标签、占位符、空状态、状态文案与校验提示。

#### 场景:工具栏文案渲染
- **当** 控制台渲染工具栏中的应用标题、搜索占位符与操作按钮
- **那么** 系统必须通过 `L10n` 从 `Localizable` 键读取并渲染文案，而不是在 SwiftUI 视图中直接写入展示字符串

### 需求:macOS 控制台必须提供英文与简体中文文案
macOS SwiftUI 控制台必须至少支持 `en` 与 `zh-Hans` 两种语言，并且同一功能页面在两种语言下都必须有可用本地化文案。

#### 场景:系统语言切换到简体中文
- **当** 操作系统语言为简体中文并启动控制台
- **那么** 控制台必须优先显示 `zh-Hans` 文案；对于缺失的键必须回退到英文值，而不是显示键名或空白文本

### 需求:产品名在所有语言环境中必须统一为 Bridging IO
控制台中涉及产品名称的所有展示位置必须使用同一品牌键，并且英文与简体中文环境下都必须显示 `Bridging IO`。

#### 场景:中英文环境下查看产品标题
- **当** 用户分别在英文与简体中文环境下查看应用标题或品牌位
- **那么** 系统必须显示完全一致的产品名 `Bridging IO`，禁止显示其他拼写或中文别名

### 需求:新增显示文案必须通过本地化校验
项目必须提供自动化校验以阻止新增硬编码显示文案，并验证 `en` 与 `zh-Hans` 的键集合一致性。

#### 场景:提交包含硬编码显示文本的 UI 变更
- **当** 新增或修改代码在显示路径中直接写入用户可见字面量文本
- **那么** 校验流程必须失败并提示修复，要求改为本地化键调用后方可通过
